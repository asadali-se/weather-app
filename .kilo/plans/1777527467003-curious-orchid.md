## Step 1: 5-Day Forecast + Hourly Forecast + Enhanced Current Weather

### Sub-step 1A: Backend — Add Forecast Endpoint

**Goal**: Create a new API endpoint `GET /api/forecast/?city=` that returns:
1. A list of daily summaries for the next 5 days
2. Hourly data for the next 24 hours (today)

**What you need to learn**:
- The OpenWeatherMap **5-day forecast API**: `https://api.openweathermap.org/data/2.5/forecast?q={city}&appid={key}&units=metric`
- This returns weather data in **3-hour intervals** (40 entries across 5 days)
- You'll need to **aggregate** the 3-hour entries into daily summaries (min/max temp, most common description, etc.)

**Files to modify**:

1. **`server/weather_api/views.py`** — Add a new view function called `get_forecast`
   - Copy the structure of the existing `get_weather` function (same error handling pattern)
   - Call the forecast API URL instead of the current weather URL
   - The raw API response has a `list` array — each item has `dt_txt` (datetime string like `"2026-04-30 15:00:00"`), `main.temp`, `main.humidity`, `weather[0].description`, `weather[0].icon`, `wind.speed`, `pop` (probability of precipitation)
   - **Your task**: Group the 3-hour items by date (extract the date part from `dt_txt`), then for each date compute:
     - `date` — the date string
     - `temp_min` — minimum temperature across all 3-hour entries for that day
     - `temp_max` — maximum temperature across all 3-hour entries for that day
     - `description` — the description from the **noon** entry (the `dt_txt` containing "12:00:00"), or fall back to the first entry
     - `icon` — same logic as description (pick noon's icon)
     - `humidity` — average of all entries for that day
     - `wind_speed` — average of all entries for that day
     - `pop` — maximum probability of precipitation for that day
   - Return two things in the response:
     ```json
     {
       "daily": [ ...5 day summaries... ],
       "hourly": [ ...first 8 entries from the raw list (covers next 24 hours)... ]
     }
     ```
   - For `hourly`, just take the first 8 items from the raw `data['list']` and reshape each one to: `{ "dt_txt": "...", "temp": ..., "description": "...", "icon": "...", "humidity": ..., "wind_speed": ... }`

   **Hint for grouping**: Use Python's `itertools.groupby` or a dictionary keyed by date string. Something like:
   ```python
   from collections import defaultdict
   days = defaultdict(list)
   for item in data['list']:
       date = item['dt_txt'].split(' ')[0]  # "2026-04-30"
       days[date].append(item)
   ```

2. **`server/weather_api/urls.py`** — Add a new URL path
   - Add `path('forecast/', views.get_forecast, name='get-forecast')` to `urlpatterns`

**How to test**: Start the server (`python manage.py runserver`) and visit `http://127.0.0.1:8000/api/forecast/?city=London` in your browser.

### Sub-step 1B: Backend — Enhance Current Weather Response

**Goal**: Return more data from the existing `/api/weather/` endpoint.

**What you need to learn**: The current weather API response contains more fields than you're currently using. Check the full response by visiting `http://api.openweathermap.org/data/2.5/weather?q=London&appid=YOUR_KEY&units=metric` in your browser.

**File to modify**: `server/weather_api/views.py`

**Your task**: Add these fields to the `weather_data` dictionary in the existing `get_weather` function:
- `icon` — from `data['weather'][0]['icon']` (weather icon code like `"01d"`, `"02n"`)
- `feels_like` — from `data['main']['feels_like']`
- `temp_min` — from `data['main']['temp_min']`
- `temp_max` — from `data['main']['temp_max']`
- `visibility` — from `data['visibility']` (in meters)
- `pressure` — from `data['main']['pressure']` (in hPa)
- `country` — from `data['sys']['country']`
- `lat` — from `data['coord']['lat']`
- `lon` — from `data['coord']['lon']`

   ```typescript
     description: string
     icon: string
     humidity: number
     wind_speed: number
     visibility: number
     pressure: number
     lat: number

   }
   ```

2. **Create new interfaces** for the forecast:
   ```typescript
   export interface ForecastDay {
     date: string
     temp_min: number
     temp_max: number
     description: string
     icon: string
     humidity: number
     wind_speed: number
     pop: number
   }

   export interface HourlyForecast {
     dt_txt: string
     temp: number
     description: string
     icon: string
     humidity: number
     wind_speed: number
   }

   export interface ForecastResponse {
     daily: ForecastDay[]
     hourly: HourlyForecast[]
   }
   ```

3. **Create a new fetch function** `getForecast(city)`:
   - Same pattern as `getCurrentWeather` but calls `/api/forecast/?city={city}`
   - Returns `ForecastResponse`

### Sub-step 1D: Frontend — Create Reusable Components

**Concept to learn**: React components let you break your UI into independent, reusable pieces. Instead of one massive `page.tsx`, you extract parts into their own files.

**Directory**: `client/app/components/` (already exists, currently empty)

**Components to create**:

1. **`WeatherIcon.tsx`** — Simple component that renders a weather icon
   - **Props**: `iconCode: string` (e.g. `"01d"`), `size?: number` (default 50)
   - The icon URL pattern is: `https://openweathermap.org/img/wn/{iconCode}@2x.png`
   - Render it as an `<img>` tag with the appropriate width/height

2. **`CurrentWeather.tsx`** — Extract the current weather display from `page.tsx`
   - **Props**: `weather: WeatherResponse` (use the updated interface)
   - Move the JSX that currently renders the weather card (temperature, humidity, wind speed) into this component
   - **Add**: weather icon (using `WeatherIcon`), feels like temp, min/max temp, visibility, pressure, country flag
   - **Tailwind tips**:
     - `grid grid-cols-3 gap-3` for a 3-column stats grid
     - Use emojis for labels or keep text labels like "Feels Like", "Visibility", etc.

3. **`HourlyForecast.tsx`** — Horizontal row of hourly cards
   - **Props**: `hourly: HourlyForecast[]`
   - Display each hour as a small card showing: time (extract hour from `dt_txt`), icon, temperature
   - Use a **wrapping grid** layout: `grid grid-cols-4 sm:grid-cols-8 gap-2`

4. **`DailyForecast.tsx`** — Grid of 5-day forecast cards
   - **Props**: `daily: ForecastDay[]`
   - Each card shows: day name (convert date string to weekday), icon, hi/lo temp, description, precipitation chance
   - Use a **wrapping grid** layout: `grid grid-cols-2 sm:grid-cols-3 md:grid-cols-5 gap-3`
   - To convert a date string like `"2026-04-30"` to a weekday name: `new Date(dateString).toLocaleDateString('en-US', { weekday: 'short' })`
